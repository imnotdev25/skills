# Tech-Stack Interview

Run this **before** writing code, docs, or scaffolding. Use `ask_user_input_v0` so the user can tap options on mobile.

## Step 1 — Fixed core (always ask, in one batch)

Ask these four in a single `ask_user_input_v0` call:

1. **Primary language**
   - Options: `Python`, `TypeScript / Node`, `Go`, `Rust`, `Other (specify)`
2. **Framework / runtime**
   - Provide options conditioned on the language hint if the user has already mentioned one in chat. Otherwise: `None / library`, `Web API framework`, `Full-stack web`, `CLI`, `Other`.
3. **Datastore**
   - Options: `Postgres`, `MySQL`, `SQLite`, `MongoDB`, `Redis only`, `None / files`, `Other`
4. **Deployment target**
   - Options: `Docker / container`, `Serverless (Lambda / Modal / Cloud Run)`, `VM / bare metal`, `Local only`, `Other`

Don't pad the batch with more than four questions in one turn — taps fatigue. If the user types "Other" anywhere, follow up with a free-text ask.

## Step 2 — Adaptive follow-ups (only what's still ambiguous)

Pick follow-ups from this menu based on the core answers. Skip any that are already implied.

| If core said... | Ask follow-up |
|---|---|
| Python | Package manager: `uv`, `poetry`, `pip + venv`, `conda` |
| TypeScript / Node | Package manager: `pnpm`, `npm`, `yarn`, `bun`; runtime: `Node`, `Bun`, `Deno` |
| Go | Module path, target Go version |
| Rust | Edition, target (binary / library / both) |
| Any web framework | Auth model: `JWT`, `session`, `OAuth provider`, `none yet` |
| Any DB | ORM / query layer: language-appropriate options + `raw SQL` |
| Serverless | Specific platform: `AWS Lambda`, `Modal`, `Cloudflare Workers`, `Vercel`, `GCP Cloud Run`, `Other` |
| Docker | Orchestrator: `none`, `compose`, `Kubernetes`, `Nomad`, `ECS` |

Also, regardless of stack, ask once:

- **Testing framework** (language-appropriate options + "decide later").
- **Logging library** (language-appropriate; flag that semantic logging is required regardless of choice).
- **Lint / formatter** (language-appropriate; offer the conventional default as the first option).
- **CI platform**: `GitHub Actions`, `GitLab CI`, `none yet`, `Other`.

## Step 3 — Capture answers

Write the interview result to `Docs/STACK.md` immediately. Format:

```markdown

| Layer | Choice | Notes |
|---|---|---|
| Language | <answer> | <version pin if known> |
| Framework | <answer> | |
| Datastore | <answer> | |
| Deployment | <answer> | |
| Package manager | <answer> | |
| Tests | <answer> | |
| Logging | <answer> | |
| Lint / format | <answer> | |
| CI | <answer> | |

_Decided: <YYYY-MM-DD>. Revisit on major version migration._
```

This file is the source of truth for stack choices. Any later code generated by the skill must match this file; if a question comes up that contradicts it, ask the user before deviating.

## What NOT to ask

- Don't ask the user to justify a choice. Capture and move on.
- Don't ask about features, scope, or product details here — that comes after the stack is fixed.
- Don't list more than 5 options per question.
